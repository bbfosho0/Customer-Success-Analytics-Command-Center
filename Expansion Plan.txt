# 3. Replace Placeholder ETL With Real Transformation

Use **Polars + DuckDB + Parquet**.

Why this combo:

* **Polars** proves Python data transformation skill
* **DuckDB** proves SQL analytics skill locally
* **Parquet** keeps the AWS/S3/Glue lakehouse story
* **FastAPI** can read curated outputs
* **BI tools** can consume CSV extracts

```text
Raw CSV / JSON
   ↓
Polars validation and cleaning
   ↓
Curated Parquet tables
   ↓
DuckDB SQL marts
   ↓
FastAPI endpoints
   ↓
Next.js dashboard
   ↓
BI exports for Tableau / CRM Analytics
```

| Expansion opportunity segments | Sales + CS crossover         |
| SLA and CSAT trends            | Support operations analytics |

## Example Metrics

### Churn Rate

```text
churn_rate = churned_customers / customers_active_at_period_start
```

### Retention Rate

```text
retention_rate = customers_active_at_period_end / customers_active_at_period_start
```

### LTV

```text
ltv = average_monthly_revenue_per_account / monthly_churn_rate
```

Better version:

```text
ltv = average_monthly_revenue_per_account * gross_margin / monthly_churn_rate
```

### Health Score

Use weighted scoring:

```text
health_score =
  product_usage_score * 0.35
+ payment_health_score * 0.20
+ support_experience_score * 0.25
+ engagement_score * 0.20
```

Then classify:

```text
80-100 = Healthy
60-79 = Watch
40-59 = At Risk
0-39 = Critical
```

# 5. BI Tools Strategy

## Best Choice

Use **Tableau Public** first, then make the project **Salesforce CRM Analytics aware**.

Reason: TouchBistro publicly connects Salesforce and Tableau in their analytics story. ([Salesforce][5]) Salesforce CRM Analytics is also relevant because it uses datasets, recipes, and dashboards. Salesforce describes CRM Analytics datasets as related data that can come from many sources. ([Salesforce][6]) Salesforce Data Prep recipes are used to clean, transform, enrich, and load data into targets. ([Salesforce][7])

## Tableau Dashboard Pages

1. **Executive Overview**
2. **Churn Risk**
3. **Retention Cohorts**
4. **Customer Health**
5. **Revenue / LTV**
6. **Support Drivers**

## Salesforce CRM Analytics Angle

Do not fake Salesforce integration. Instead, create a credible CRMA-readiness layer:

```text
bi/salesforce_crma/dataset_mapping.md
```

Include mappings like:

| Repo Dataset                   | Salesforce Equivalent                 |
| ------------------------------ | ------------------------------------- |
| `accounts.csv`                 | Account                               |
| `opportunities.csv`            | Opportunity                           |
| `support_interactions.csv`     | Case                                  |
| `customer_success_touches.csv` | Task / Event                          |
| `subscriptions.csv`            | Contract / Subscription custom object |
| `invoices.csv`                 | Billing / Revenue object              |

Also include:

```text
bi/salesforce_crma/recipe_plan.md
```

Describe a CRM Analytics recipe:

```text
Account
  ↓ joined to Subscription
  ↓ joined to Case / Support Interaction
  ↓ joined to Product Usage
  ↓ joined to Invoice
  ↓ output Customer_360 dataset
```

Salesforce CRM Analytics supports recipe outputs to datasets, CSV, Data 360 lake objects, remote locations, and Amazon S3, so this mapping is technically aligned. ([Salesforce][8])
