# Custom Dashboard LWC

## Purpose

`customerSuccessCommandCenter` is the polished Salesforce frontend for the Customer Success Command Center. It is intentionally separate from the CRM Analytics dashboard metadata in `salesforce/force-app/main/default/wave/`.

Use the LWC when the goal is:

- a refined executive-facing landing experience,
- responsive desktop, tablet, and mobile presentation,
- a branded command-center layout that matches the GitHub Pages and Figma direction more closely than a `.wdash`,
- safe rendering even when CRM Analytics assets or final navigation targets are not yet wired.

Use the CRM Analytics dashboards when the goal is:

- metrics sourced from Analytics datasets,
- drilldown exploration,
- preserved dashboard bindings, steps, filters, and dataset logic,
- deployment of the analytics metadata layer itself.

## Current Implementation

The LWC lives at `salesforce/force-app/main/default/lwc/customerSuccessCommandCenter/` and now uses Apex-backed packaged sample data through `CustomerSuccessDashboardController`.

The bundle includes:

- header banner with sample-data state messaging,
- local filter bar for portfolio, segment, risk band, region, and time window,
- KPI summary cards,
- risk exposure and portfolio health visuals built with native HTML and CSS,
- health and risk summary cards,
- priority queue table,
- owner attention summary card.

Data behavior:

- the user-facing dashboards read a packaged static-resource payload derived from the checked-in CSV datasets under `data/salesforce_crma/`,
- the payload is generated by `python salesforce/scripts/build_dashboard_sample_resources.py`,
- Apex parses that packaged sample payload and returns the view models used by the four LWC pages.

The `.wdash` files remain untouched.

## Relationship To CRMA

The LWC is the presentation layer.

CRM Analytics remains the analytics metadata layer.

That means:

- `Landing_Page.wdash` and related dashboards stay intact as analytics assets,
- CRMA dashboards remain retained backend/reference assets for now,
- the LWC should not be treated as a replacement for dataset-backed analytics logic,
- design refinements should generally happen in the LWC, not by forcing the `.wdash` to become pixel-perfect.

## How To Access It

The `customerSuccessCommandCenter` LWC is the rendered UI.

The visible Salesforce entry point is a dedicated Lightning app with:

- Landing tab: `CustomerSuccessCommandCenter_Page` labeled `Command Center`
- Drilldown tabs:
  - `AtRiskDrilldown_Page`
  - `ExpansionPipeline_Page`
  - `RetentionCohorts_Page`

After deployment:

1. Open Lightning App Launcher or app navigation.
2. Find `Customer Success Command Center`.
3. Open the app and land on `Command Center`.
4. Use the top nav for `At-Risk Drilldown`, `Expansion Pipeline`, and `Retention Cohorts`.

The app also includes a permission set, `CustomerSuccessCommandCenterAccess`, that grants visibility to the app and drilldown tabs.

## Drilldown Pages

The component drilldown actions route to first-class in-app LWC destinations for:

- `At_Risk_Account_Dashboard`
- `Expansion_Pipeline_Dashboard`
- `Retention_Cohort_Dashboard`

Those drilldown tabs are custom LWC pages. The CRM Analytics dashboards are preserved in the org and repo, but they are no longer the surfaced user experience for these app sections.

## Next Steps For Live Data

Recommended path for production hardening:

1. Replace the packaged sample payload with a real integration boundary only after the target Salesforce or external system mappings are confirmed.
2. Move client-side filtering server-side if dashboard row counts grow beyond what is comfortable for a single initial payload.
3. Add page-level loading skeletons, empty states, and Jest coverage for the Apex-fed paths.
4. If more Salesforce frontends will share this look and feel, extract the mirrored design tokens and shared formatting helpers into a broader reusable theme pattern.

## Build And Deploy

Regenerate the packaged sample payload before deploying dashboard data changes:

```powershell
python salesforce/scripts/build_dashboard_sample_resources.py
```

Then deploy the app metadata:

```powershell
cd salesforce
sf project deploy start --target-org <org-alias> --manifest manifest/package.xml --wait 30
```
